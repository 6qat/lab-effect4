Two parallel adapter modules (`tcp-connection-bun.ts`, `tcp-connection-nodejs.ts`) implement the same contract: each exports an `adapter` function consumed by `makeTcpStreamEngine` from `./tcp-stream-engine.js`, returning an `Effect.callback` that yields a `RawSocketHandle` with `write`/`close`. The adapter bridges platform-native socket APIs (`Bun.connect` / `node:net` + `node:tls`) into the shared `TcpStreamEngineAdapterEvent` event stream (`Data`-tagged union of Ready/Data/Drain/Close/Error). Each file then exposes a `Layer.succeed(TcpStreamEngine, engine)` live layer plus a convenience layer via `makeConvenienceLayer`, re-exports `ConnectionConfigLive` and types from `tcp-connection-common.js` and `tcp-stream-engine.js`, and aliases `ConnectionConfigNodejsLive` as `ConnectionConfigNodeLive` (Node) or `TcpStreamLive` (Bun) for ergonomic imports. `tcp-connection-http-example.ts` is a standalone executable that parses CLI args (`--engine=bun|nodejs|platform`), builds a `ConnectionConfigShape` from an http(s) URL, and wires one of three program variants (`requestProgramBun`, `requestProgramNodejs`, `requestProgramPlatform`) through `Effect.provide`, demonstrating how consumers swap implementations purely via Layer composition. Dependency direction is strictly inward: adapters depend on `tcp-stream-engine.js` and `tcp-connection-common.js`; the example depends on both adapters but they do not depend on it.

Two cooperating layers inside one module:
- `line-framing.ts` is a pure, framework-agnostic utility: it pipes an `Effect.Stream<Uint8Array>` through `Stream.decodeText` + `Stream.splitLines` to produce `Stream<string>`, handling multi-packet reassembly and batched line emission.
- `cedro-protocol.ts` builds on top via the `TcpStream` service from `./tcp-connection.js`. It defines two Effect Context services — `CedroConfig` (credentials + magic token) and `CedroClient` (authenticate/subscribe/rawStream/lines) — constructed by `makeCedroClient`, which composes the config, calls `frameLines(tcp.stream)` for the framed view, and exposes `Layer.effect` / `Layer.succeed` live layers (`CedroClientLive`, `CedroConfigLive`).
- Error modeling uses `Data.TaggedError("CedroProtocolError")`; pure command formatting functions return `Result.Result<string, CedroProtocolError>` and are lifted into I/O via `Effect.fromResult`, keeping validation separate from side effects. Dependency direction is strictly inward: protocol → line-framing → effect core; no reverse imports.

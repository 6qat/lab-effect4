Three-layer split inside the module:
- `tcp-connection-common.ts` defines shared contracts (`TcpStreamShape`, `ConnectionConfigShape`, `RetryPolicyConfig`) and error types (`TcpStreamError`, `ConnectionConfigError`) plus validation helpers (`validateHostAndPort`, `buildDefaultRetrySchedule`).
- `tcp-stream-engine.ts` is the pure orchestration layer: it exposes a `ColdAdapter` protocol `(config, emit) => Effect<RawSocketHandle>` and builds it into `TcpStreamEngineShape` via `makeTcpStreamEngine`, managing connection lifecycle (connecting/ready/closed phases), an unbounded event queue, connect timeouts (`withConnectTimeout`), optional exponential+jitter retry, and finally wraps everything in `makeTcpStream` which yields a `TcpStream` service with backpressure-aware writes (Semaphore + drain Deferred).
- Platform adapters (`tcp-connection-bun.ts`, `tcp-connection-nodejs.ts`, `tcp-connection-platform.ts`) each implement the `ColdAdapter` using their native socket API (Bun.connect, node:net/node:tls, or @effect/platform-bun BunSocket) and export `Layer.succeed(TcpStreamEngine, engine)` plus convenience layers built through `makeConvenienceLayer`.
- Dependency direction is strictly inward: platform files depend on engine → common; the engine depends only on common. `tcp-connection.ts` is a backward-compat re-export of the Bun adapter.
- The `tcp-connection-test-suite.ts` and `tcp-connection-http-example.ts` are consumer fixtures demonstrating how to wire the layers.
